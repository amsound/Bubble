Cart Setup: what it does today, and who draws each part

An audit of the egui window (crates/bubble-app, audio_setup_window). It opens from quick edit's Cart Setup… and the Cart menu, edits a draft of one cart, and lets you audition it while you trim. Today this window exists only in the old egui app; the Slint app lists Cart Setup… as "not in this interface yet". The new version is Slint's. Each part is marked: System means macOS or Windows draws it (as the alerts and menus now are), Slint means Slint draws it inside the system window, styled to each platform as quick edit is.

Decisions

  1. Decided: keep OK / Cancel. Edits go to a draft and apply on OK, while what you hear (gain, speed, loop, trims) follows live.
  2. Decided: Trigger becomes Hotkey. Open: whether a hotkey keeps its "what it does" choice (Play/Stop, Play only, Stop only), and whether MIDI shows only when MIDI input is on.
  3. Speed Bar's Open… stays until the Speed Bar window is ported (it is the next window on the list).

Why the controls are drawn, not system ones

Slint opens Cart Setup as a real system window (title bar, resize, full screen, Window menu), but draws what is inside. Making the sliders, fields and buttons the system's own would mean building this window twice by hand, in AppKit for the Mac and in Win32 for Windows, and the waveform, meter and readouts would still be drawn by Bubble on both. So the plan matches quick edit: drawn controls in each platform's style, and everything the system does offer used as it is: the window, every pop-up's menu, the colour picker, the Open panel.
